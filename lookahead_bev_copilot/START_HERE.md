# Copilot への実装依頼｜推論 BEV に参照経路と各 step の注視点を描く

開いている MetaDrive 派生プロジェクトに以下を実装し、通常の推論入口で動作確認まで行ってください。ゴールは、利用者が交差点の映像を見て「どの車線を通る予定か」「この操作を決めたとき、車はどこを先読みしていたか」を読み取れることです。実装先はユーザーのプロジェクトです。このファイルのある資料フォルダは参照用です。

作業は開いているプロジェクトのルートから、その PC のシェルと既存の Python 環境で進めます。同梱差分の基準は移植元 `c66ac39`、描画は MetaDrive 0.4.3（`85e5dadc`）です。派生先との照合には、そちらで使われているソースと実行結果を使ってください。

## 1. まず現地のコードで四つの接続先を見つける

現在の作業差分を確認し、推論を起動するコマンドから順に追ってください。以下の名前は移植元の例です。名前やディレクトリが異なる場合も、データを作る処理と使う処理の関係で特定します。

| 探すもの | 移植元での手掛かり |
| --- | --- |
| 方策が行動を選び、環境を1回進める箇所 | `evaluate.py` の `model.predict(obs)` → `env.step(action)` |
| その観測の注視点を計算した経路 | reset 後の `MetaDrivePreviewProvider` が持つ `ReferencePath`。外側の環境から `get_wrapper_attr("reference_path")` で取得 |
| 注視点の世界座標と有効フラグ | step の `info["lookahead_learning"]["pre_step"]["preview"]` 内の `q_xy` と `preview_valid` |
| 実際にユーザーが見る BEV とその出力先 | `env.render(mode="topdown")` → 地図に重ね描き → パネル合成 → GIF・MP4・PNG。派生先のライブ表示が別経路ならその合成点も確認 |

検索対象は資料フォルダの外にある派生先のコードです。検索語は `lookahead`、`preview`、`waypoint`、`pure_pursuit`、`topdown`、`bev`、`render`。最初に観測・操舵と対象点の対応を確かめてから、既存実装に足りない差分を編集します。

## 2. 描く線と点

- **青緑の線は、先読みに実際に使った車線中心の参照経路。** 移植元では reset 後にナビの道路順と開始時の車線番号で構築した、接続検証済みの区間列です。その同じ経路オブジェクトを読み取り用に渡します。車線なら各区間の両端を含め、`lane.position(s, 0)` を最大約 1 m 間隔でサンプルします。既存の折れ線表現なら元の点列を使います。交差点では選ばれた出口までの直線・円弧をたどり、検証済み区間の終端で線を止めます。エピソードごとに更新し、固定経路のサンプリングは1回で十分です。
- **橙色の輪は、そのフレームで報告する行動を決めたときの注視点。** `(x, y)` は世界座標です。元実装のBEVには step 後の車両が写り、輪だけが行動直前の値です。距離指定、時間指定、PP の重みがゼロの設定でも、実際に観測へ渡した点を使います。停止時などは座標が残っても無効になるので、フラグが真で座標が有限なときだけ輪を描きます。無効時は輪を消し、凡例に「注視点なし」と表示します。
- **データを公開する位置。** 点が内部にしかない派生では、既存の先読み計算が得た点と有効フラグを、観測を作った時点で保存して描画に渡してください。step 後の新しい観測点は次の行動用です。正規化・クリップ前の座標を保存すれば、距離・時間の式を描画側で再計算せずに済みます。予測報酬用の目標、実走行の軌跡、最寄り車線や他車の目標を代用すると意味が変わります。

```text
reset → そのエピソードの参照経路を取得 → 最初の観測と注視点を対応づける
各 step:
    今の観測に対応する注視点と valid を確保
    既存の方策で行動を選択 → 既存の env.step を1回実行
    step 後の BEV に経路を重ね、確保した点が有効なら輪を重ねる
    同じ合成画像を既存の表示・保存先へ渡す
```

step の戻り値に行動前スナップショットが既にあれば、それをそのまま利用できます。並列環境や自動 reset がある場合は、経路・注視点・車両を同じ環境の同じ episode に対応づけ、終端ステップまで描画します。先読みを使わないモデル・設定には従来の BEV を表示します。派生先全体に単一の注視点を参照する処理が存在しない場合は、取得できる実データまで表示を接続し、実際に足りない情報を報告してください。新しいモデル入力や制御則の導入はこの描画の範囲を超えます。

## 3. 地図に重ねて推論出力へ接続する

1. エピソード全体の固定経路を見渡せる画角にします。移植元の 600 × 600 px の固定俯瞰は、経路の外接矩形の中心をカメラ中心とし、四辺に少なくとも約 24 px の余白を取ります。座標変換は実際のレンダラの原点・縮尺・Y 軸の向き・切り出し位置に合わせます。派生先に追従・回転表示がある場合は、その表示の変換も使います。
2. 地図領域に青緑の経路線を置き、車両・交通・走行履歴の色を保ちます。橙色の輪は中心が正しい投影画素に来るように描き、凡例で線と輪を識別できるようにします。重ね描きはパネルや映像エンコーダへ渡す前の共通箇所に接続します。内部に録画バッファを持つ形式では、その保存画像にも反映してください。
3. 通常の推論・録画操作で表示できる状態にします。既存の観測次元、報酬、行動、モデル読込、step 数、出力のタイミングを保ちます。録画もライブ表示も無効なら描画の計算を省きます。既存の変更を含むファイルは必要な箇所だけ編集してください。

## 4. 完了を判定する

- **最小テスト**。行動前の注視点が無効（座標は残存）、step 後は有効になる2ステップを使います。1枚目は線のみ、2枚目には前の step の終了時に得た点の位置に輪が出ることを確認します。時間先読みがない派生では異なる二つの実測点または小さなテスト入力で同じ時刻対応を検査します。
- **交差点**。短い左折または右折で、入口直線→交差点内の円弧→出口の連続した経路を確認します。少なくとも1枚で行動直前の世界座標をカメラで画面に投影し、画像上の輪の中心と照合します。reset、無効な注視点、先読みオフ、録画オフも既存テストまたは短い確認でカバーしてください。
- **通常入口**。普段使う評価・推論コマンドを短い条件で通し、一時出力先で実ファイルを開きます。既存の PNG・GIF・MP4 やライブ表示で同じ点が見えることと、フレーム数・再生時間を確認します。移植元では別の実験名か一時出力先を使うと既存結果を保てます（`--output-prefix` はログ名の指定です）。互換モデルがない場合は、観測空間・行動空間・先読み設定のメタデータを合わせた未学習の一時モデルで確認できます。交差点の描画例は固定行動や固定ルールでも検証できます。使った条件を明記します。長時間学習は不要です。
- **利用者への回答**。変更ファイル、実際の経路と点の取得元、実行したコマンド、見本 PNG と短い動画の保存場所、検証結果を日本語で報告します。起動できない箇所がある場合も、手元で可能な実装・テストまで進め、実測と未確認の範囲を明記します。
