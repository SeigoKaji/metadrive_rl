## 判定ルール

- `success` の stage だけを report の最新結果として扱い、`failed`、`pending`、`running`、`skipped` は未完了または未実行と表示します。
- model/adapter/environment 作成、run 全体の reset、要求 seed の適用・readbackなど共通初期化の失敗は run 全体を無効にします。初期化後の pattern 固有 intervention、policy inference、Action decode、`env.step()`、telemetry の失敗はその pattern の `aborted` 記録と理由を残し、別 pattern を継続します。
- planned `max_steps=500` は上限で、自然終了した episode の実 step 数・duration と別に扱います。duration は測定値がなければ `None`、既知 interval のみなら known partial sum と partial status、pair status が unknown なら P00 差の集約対象外です。
- variant 変更として許可するのは、明示された replacement/intervention recommendation の追加・変更だけです。入力の source、型、順序、normalization、符号、range、coupling、validity、invalid sentinel の変更は新しい通常走行を要求します。
- offline reuse の親条件（scenario、seed、environment、adapter、model、preprocess、保存 snapshot/reference/source）は一致が必要です。差分がある場合、子 run を作らず拒否します。
- 動画は `video.enabled = true` と `video.patterns = ["P00", "<重点pattern>"]` で保存対象を明示します。`closed-loop --patterns P00,<重点pattern>` は走行対象の選択であり、`video.patterns` はその中の動画保存対象を選びます。未指定は走行対象全件です。全件無効は `video.enabled = false` で指定します。
- fake/保存結果の値は実車両の性能や一般化した重要度の主張に使いません。
