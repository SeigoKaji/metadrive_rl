# 前方注視を使う強化学習：ドキュメント

`lookahead_learning` は、既存のMetaDrive環境に「前方注視点の入力」と
「Pure Pursuitの操舵参照を使う報酬」を追加して比較するモジュールです。

## 名前と違い

| 呼び方 | CLIの `--mode` | 方策への入力 | 報酬 |
|---|---|---|---|
| 基準環境 | `baseline` | 既存観測 | 既存報酬 |
| 前方注視点入力 | `lookahead_obs` | 既存観測＋前方注視点の3値 | 既存報酬 |
| 前方注視点入力＋PP参照報酬 | `lookahead_obs_pp_reward` | `lookahead_obs`と同じ | 既存報酬＋操舵不一致ペナルティ |

`obs` は observation（観測・入力）、`PP` は Pure Pursuit（幾何から操舵参照を
計算する方法）の略です。長い名前を使うことで、保存先やコマンドを後から見ても
「入力だけを追加した実験」と「入力と報酬を追加した実験」を区別できます。

入力と報酬を追加するモードでも、**操舵・加減速を選ぶのはRL方策です**。
PPが計算する `u_pp` は報酬の比較基準で、車両への操舵を上書きしません。
また、PPの値そのものを入力へ追加する仕様でもありません。

## 最初の確認

ホストの `train.py`、`env_factory.py` と同じ階層に `lookahead_learning/` を配置し、
ホストのライブラリが入ったPythonで実行します。

```bash
python -B -m lookahead_learning --help
python -B -m lookahead_learning doctor --base-config configs/official_start_lane_return.toml
```

今回確認したホストの観測は **259次元**でした。この実験の前提は、開始レーンに
関する3値を既に含む、意味が確認された **262次元**のホストです。
したがって現在は、診断・単体テスト・raw環境の診断を実行できますが、通常の学習・
評価は観測契約の不一致として拒否されます。別PCに262次元の環境があっても、
3値の意味を監査し、この追加モジュールの対応情報に登録する工程が必要です。
数を合わせるためのpaddingや、既存環境への自動パッチは行いません。

[実行手順](run.md)では、現在実行できる確認と、対応ホストの確認後に使う学習手順を
分けて説明しています。実262/265次元のPPO学習と、ふらつき改善の性能比較は未実施です。

## 配布物

実行に必要なのは `lookahead_learning/` 直下の `.py` 一式です。
この `docs/` も一緒にコピーすると、移植先で手順と数式を読めます。
Markdown文書は起動時に読み込まれず、新しい設定ファイルとして使われることもありません。

起動コマンドは `python -B -m lookahead_learning ...` を使います。ホスト本来の `train.py` 等の
起動方法は変わりません。以前に生成したモデル・ログ・監査結果は変更しません。
